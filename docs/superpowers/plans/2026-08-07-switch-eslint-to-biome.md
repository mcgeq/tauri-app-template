# Switch Frontend Lint/Format from ESLint to Biome

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace ESLint + @antfu/eslint-config with Biome for the frontend's linting, formatting, and import organization, while keeping the `pnpm lint` / `pnpm lint:fix` contract and CI green.

**Architecture:** Biome is a single Rust-based tool that replaces ESLint (linting), the antfu stylistic rules, dprint/eslint-plugin-format (formatting), and the import-sort plugin (organize imports). Declarative `biome.json` at repo root replaces `eslint.config.js`. `lint-staged` + `simple-git-hooks` stay intact and just point at `biome check --write`. Script names stay identical (`lint`, `lint:fix`) so `ci.yml`, `check`, `check:all` need no changes.

**Tech Stack:** `@biomejs/biome` v2.4.x, VCS integration (`vcs.useIgnoreFile`) to respect `.gitignore`, formatter + linter + organize-imports in one binary.

## Analysis Summary (why the plan looks like this)

Verified against the repo and Biome 2.4.x docs:

- Current ESLint setup: `eslint.config.js` (antfu: react+ts, dprint formatters for css/html/md, stylistic indent 2 / single quotes / semis), scripts `lint`/`lint:fix`, lint-staged `*.{ts,tsx}` + `*.{css,json,md}`, pre-commit `pnpm lint-staged`.
- Biome 2.4.8 (current stable) fully supports formatting + linting for JS/TS/JSX/TSX/JSON/JSONC/CSS/HTML/GraphQL. **Markdown and YAML formatting are NOT available yet** (⌛, gated behind Rust features). Consequence (intentional behavior change): Markdown files are no longer auto-formatted; `.md` goes to the ignore list and drops out of lint-staged.
- Biome's `vcs.enabled + useIgnoreFile: true` makes it honor `.gitignore`, automatically skipping `dist/`, `coverage/`, `app/`, `target/`, `node_modules/`, and generated `src/auto-imports.d.ts`.
- react-hooks parity: Biome has `lint/correctness/useExhaustiveDependencies` (= exhaustive-deps) and `lint/correctness/useHookAtTopLevel` (= rules-of-hooks), both recommended and React-domain-gated (auto-active because this project imports React).
- `noUnusedVariables` (recommended) natively ignores `_`-prefixed names — same semantics as the old `argsIgnorePattern`/`varsIgnorePattern`/`caughtErrorsIgnorePattern` overrides.
- The single `// eslint-disable-next-line react/no-unnecessary-use-prefix` comment has no Biome counterpart; it is deleted (the rule doesn't exist in Biome).
- antfu default print width is 120; Biome default is 80 → set `lineWidth: 120` and `indentStyle: space`/`indentWidth: 2` to minimize the one-time reformat diff.
- One-time reformat is expected; the requester-visible diff will be mostly formatting + import-order normalization. Reviewed, not blindly accepted.

**Behavior changes introduced (documented, acceptable):**
1. Markdown formatting is dropped (Biome can't format `.md` yet).
2. `lint:` only checks the included extensions below (JS/TS/JSON/JSONC/CSS/HTML); other files (md, yaml, toml, rs, Dockerfile…) are untouched.
3. React-specific linting comes from Biome's built-in React rules, not `@eslint-react/*` or `eslint-plugin-react-hooks`; some niche antfu React rules are simply gone.
4. `pnpm-workspace.yaml` no longer has a special "react enforce settings off" override (YAML not linted at all).
